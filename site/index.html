How to read this

  • Rules win on precision and analyst workload, but they were written knowing the attack catalog. Against techniques nobody wrote a rule for they would do worse. The ML detectors never see labels.
  • ML adds recall on volume-shaped attacks such as lateral movement and vault checkout bursts, at the cost of a few extra benign alerts per day.
  • The served hybrid alerts when either the rules or the Isolation Forest alert, giving the best recall and PR-AUC.
  • New source host is the hard case: a single novelty signal sits inside benign hot-desking. Only the autoencoder (not served) flags it.
  • Synthetic data, 17 test incidents: one incident moves incident recall by about 6 points.

How it works

The same feature code runs in training, evaluation and the live API, so there is no train/serve skew.

1 · Ingest

Canonical events

Logons, vault checkouts and privileged-session commands from a simulated company or the LANL dataset, in one schema.

2 · Baseline

18 features

Per-account profile (usual hosts, hours, commands) plus trailing-hour windows: fan-out, failures, checkouts, rare tokens.

3 · Detect

Rules + Isolation Forest

PTA-style rules for precision, an unsupervised model for what nobody wrote a rule for, on one 0-100 risk scale.

4 · Explain

SHAP in plain English

Rule reasons first, then the features that pushed the score up, written in the event's own context.

5 · Triage

API + SOC dashboard

FastAPI scores events and stores alerts in SQLite; analysts mark true/false positives, which feed retraining.
